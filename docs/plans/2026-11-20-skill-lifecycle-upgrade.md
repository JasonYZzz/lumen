# Skill 导入、加载与使用机制升级实施计划

**状态**　2026-11-20 已在 Lumen 2.0.0、`c31755b` 工作区实施 M1–M4，并完成 macOS 本地验收与 M5 首轮真实模型对照。跨平台发布验收仍待 Linux、Windows 实机或 CI。结果见[实施记录](#6-实施记录)。

**交付目标**　用户能从 Web 或桌面导入团队提供的技能包，看懂其来源、限制和安装范围，确认后立即在当前工作区使用。模型按描述发现技能，用户也可指定技能。恢复旧任务时，能判断参考文件和脚本是否仍与采用的正文配套。

## 2. 用户路径与职责

1. **导入**。在 Web「设置 → 扩展能力 → Skills」选择 ZIP、文件夹或 GitHub 来源。桌面复用同一界面。已有资料库上传继续产生资料；技能导入有独立入口和确认文案。
2. **预览**。列出候选 Skill 的名称、描述、项目或用户范围、来源与版本、文件数与大小、声明脚本、影响调用的兼容诊断、同名覆盖及本地修改。多候选由用户选择精确路径，当前不可用范围说明原因。
3. **确认与使用**。用户确认所见候选与版本后，Host 执行安装并返回结果。列表立即刷新，用户可以复制手动调用命令或选择在会话中使用。导入过程只解析文件，调用 Skill 和运行脚本分别发生。
4. **管理**。界面区分“从当前会话卸载”“停用此安装”“移除受管安装”。后两项按第 5 节分批交付。显示安装来源、当前版本、同名覆盖者和启用状态，使用户能解释模型为何看到或看不到某个技能。

| 现有 Module | 本轮职责 |
|---|---|
| WorkspaceHost 与 API Adapter | 发起预览与确认，校验调用者、作用域、并发与请求身份；返回结构化结果给客户端。模型工具调用继续经 CapabilityGateway。 |
| SkillInstaller、DirectoryResourceAdapter、TaskWorkspace | 统一解析本地包与远端包，固定候选内容，沿已有目录 mutation 路径暂存、发布、验证、恢复。 |
| SkillLoader、ResourceManager | 解析兼容字段、建立可见目录、识别同名来源与激活身份。模型、CLI、TUI、Web 共用发现与加载规则。 |
| SessionContextManager、SessionRepository、ArtifactStore | 持久化激活依据与内容引用。正文、历史、压缩和恢复继续沿用现有实现。 |
| SandboxRunner、工具审批、Agent 角色 | 对实际脚本调用执行现行权限。外包声明仅用于解释和收窄行为，不能增加工具、联网、执行或 child 权限。 |

## 3. 实施批次与退出条件

建议按下表拆分可独立审核的变更。M1 可先交付；M2 与 M3 可以分别开发，Web 对用户开放上传以前须通过 M1–M3。M4 可独立发布，M5 使用前述功能的稳定版本。

| 批次 | 实现工作与交付物 | 退出条件 |
|---|---|---|
| M1　手动激活和调用兼容 | 修正资源、脚本与模型加载的资格判断；识别兼容调用策略；预览和发现报告采用同一诊断。 | 手动包不会被模型自行加载；用户在 A 会话激活后能读参考资料，B 会话和无授权 child 无法借用；重新激活、卸载与恢复均有回归。 |
| M2　会话版本一致性 | 给新激活记录绑定来源与依赖版本依据；检测变化；对旧记录提供可解释的恢复路径。 | 与前次相同的 V1/V2 实验中，V1 正文不能静默读取 V2 引用或执行 V2 脚本；用户可继续查看旧正文，并明确选择当前版本。 |
| M3　统一导入和 Web 界面 | 先交 Host 的预览／确认契约、上传适配和错误分类，再交 Web/桌面界面。GitHub、ZIP、浏览器目录及现有本地工具共用候选识别和发布验证。 | 无配置变更的旧安装能照常启动；条件不满足时界面说清原因。三个来源分别完成预览、确认、立即加载和重复提交验证。 |
| M4　共享发现与安装管理 | 可选共享根目录、来源和同名覆盖展示、逐项停用、受管更新与移除。当前会话卸载沿用原入口。 | 关闭共享发现时得到原目录；新发现根与项目首次信任一致；更新保留本地修改，移除后能指出接替生效的同名来源。 |
| M5　效果与发布验收 | 用真实模型测量选择、遵循与最终任务结果；补公开仓库成功路径、断网／限流、桌面与跨平台验证；更新用户与作者文档。 | 机械契约、产品路径、联网实测分别有证据。对自动调用效果的结论附样本、分母、配置与失败原因。 |

### M1　区分“谁可以启动”与“启动后可以做什么”

- 把名称、来源、当前会话激活记录及调用者有效权限一起传给已有读取与执行入口。普通可自动调用的 Skill 保留现有受限读取行为。手动限定的包只有在用户明确选择后，才可在该会话使用配套资源和已声明脚本；脚本继续走 EXECUTE 审批、沙箱与超时。仅凭知道包名、猜到路径或看见历史正文不构成选择。
- 检查 Host 手动调用、显式上下文激活、模型 `load_skill`、fork、重试和 child 的真实入口。激活须与已受理的用户动作对应，启动失败、忙状态或重放请求不能遗留新授权。同名覆盖或原本自动调用的包改为手动时，需要重新确认。历史记录缺少调用来源时，继续提供已保存的正文，手动限定的配套工具等显式选择后恢复。
- 基础格式沿用 `SKILL.md`；映射 Codex `agents/openai.yaml` 的 `policy.allow_implicit_invocation: false` 和已支持的 `disable-model-invocation`。两者冲突采用较严限制。对 Claude `context: fork`、`agent`、动态命令、工具预授权及 Codex 工具依赖等影响执行的声明，预览逐项说明。无法等价表达的调用限制，必须明确处理后才允许按降级方式启用。普通展示元数据不应导致整包拒载。
- 作者可查看能调用的脚本和被忽略的声明。第三方 `scripts/` 中的文件继续作为资产保留，专用执行工具只接受 Lumen 支持的声明和解释器。补一份纯文本可移植包、一份 Codex 手动包和一份含未支持执行语义的夹具。

### M2　从“保存正文”补到“使用同一版本”

- 首期采用**检测漂移并要求重新激活**。对于受管安装，复用目录内容 revision 和已验证的安装快照；读取时还须核对实际内容，不能只信任安装元数据。对于直接发现的目录包，在激活时建立同一范围的有界内容摘要，覆盖参考文件、脚本和本地 helper。资源仅按需读取；避免目录每次刷新都为所有包计算摘要。
- 使用已校验的同一版本字节，或从对应只读快照供给运行，避免“先校验、后打开”之间又发生替换。包被覆盖、移除、修改，同名来源发生变化，或旧快照缺失时，返回可区分的诊断；不得自动转读同名的其他安装。重激活后再使用新版，旧 journal 与正文仍可查阅。
- 每次读取资源或执行脚本仍检查当前会话权限、项目受信状态和 child 的有效范围。历史快照提供内容证据，不能恢复已撤销的访问或执行权限。验收包含“先激活、后撤权、再恢复”。
- 单文件技能可能与其他技能共用父目录，超限目录也无法完整建快照。保留正文激活能力，明确标注依赖未固定；需要可复现的外部资源或脚本时，引导使用独立目录包。避免把整个共享根收进会话产物。
- 通过 Session fixture 决定兼容方案。新字段须支持读旧记录；按现有 schema 升级规则处理持久格式变化，仅追加升级记录。上线前演练旧程序读取新 journal 的实际结果；遇到严格解析不兼容时，提供版本边界和恢复步骤，保留升级前副本。

### M3　统一包导入与确认

- **数据边界**。浏览器只传用户所选文件的字节与受校验的包内相对路径，不能把客户端文件夹名作为服务器本地路径。ZIP 同时支持根级 `SKILL.md`、单包装目录和多候选集合；现有 GitHub archive 的首层仓库目录剥离规则不可直接套到用户 ZIP。工作区路径源继续使用 Workspace 解析。
- **预览与发布**。预览返回有界清单、兼容诊断、目标当前 revision、候选内容摘要，可查看转义后的指令或声明脚本文本。确认绑定操作者／工作区、所选候选、作用域、版本和请求身份。远端分支变化不改变用户确认过的 commit；预览后目标发生变更则返回冲突。上传临时字节按 Host 生命周期限量保存并清理，取消、超期、重启后可重新预览。
- **写入准入**。沿用项目受信、受管用户目录授权、TaskWorkspace 启用、目录写入校验和并发边界。模型发起的安装仍受 `tools.builtins` 和 Gateway 审批约束。首版建议直接导入也沿用显式启用安装能力的配置，界面提供原因与操作指引；若决定让操作者独立于模型安装，须单独定义 Host 操作授权与测试。预览和确认都检查权限，Plan 或 child 不得借用根用户的操作。
- **资源与错误**。复用现有 32 MiB 下载／展开上限及文件数量约束；流式接收时限制字节数，统一检查归档层级、大小写冲突、重复项、符号链接、特殊文件和路径越界。区分格式不支持、无候选、多候选、超限、目标冲突、鉴权失败、GitHub 配额耗尽、网络中断和发布失败。仅在响应提供可靠信息时展示重试时间。凭据、上传内容和完整敏感路径不进入客户端诊断或 journal 摘要。
- **客户端**。设置页展示“选择来源 → 查看候选与变更 → 确认安装 → 在会话中使用”；覆盖更新明确显示现有来源与本地修改。接口以 Host 定义为准，更新 FastAPI schema、生成的 TypeScript 和 Web client。CLI 模型工具、Web、桌面共享发布结果；桌面沿用现有 Web 壳。已有配置关闭安装时，查看已发现 Skill 和手动调用仍可用。

### M4　共享目录与管理

- 建议以**显式启用、只读发现**支持工作区及用户的 `.agents/skills`。项目根须同时进入配置发现、CLI／桌面首次信任、SkillLoader、路径校验和刷新；受信工作区内的共享目录优先于用户范围，同一范围内原有 `.lumen/skills` 优先。内置范围仍最低。首版把工作区边界作为停止位置；若要支持从子目录向 Git 祖先查找，另验祖先来源信任。
- 停用按安装来源与身份保存，列出被遮蔽的同名项；定义重新启用、名称冲突与刷新后的有效项。停用后停止新的选择与辅助执行；会话中已保存的历史正文继续可审计。与会话卸载分别测试，避免永久停用被下一次扫描撤销。
- 对受管项提供按已知来源重新预览更新、查看版本差异、明确确认移除。确认前校验当前 revision、检测用户编辑；被活动执行引用时推迟移除。沿用 TaskWorkspace 的可验证 mutation，先验证目录删除与恢复能力，再开放移除入口。手工目录及共享只读项提供停用与原路径说明，不由管理界面递归删除。

### M5　真实任务评测

复用[现有 Harness 效果计划](2026-10-23-agent-quality-harness-improvement-plan.md)的隔离运行、独立评分和成本口径。现有 benchmark 有关闭 Skill 的基线，候选组须先证明测试 Skill 进入目录并能实际加载。先在 CI 做确定性契约，再以授权的真实 Provider 跑效果组。

| 样本 | 记录与判定 |
|---|---|
| 明确匹配、中文改写、多个相近技能 | 正确选用次数／应选任务数；记录预期项是否进入模型目录、是否经分页找到、实际加载哪个 Skill。 |
| 无关任务、仅手动包、禁用包 | 误触发次数／不应触发任务数；同时检查手动限定的包无用户选择时不能经工具启用。 |
| 须读引用、须运行已声明脚本、缺失依赖 | 分别记录加载、读资源、审批、脚本结果，以及独立判断的任务成功数／全部已启动尝试。 |
| 压缩、重启、版本更新、撤权后继续 | 单独报告旧正文是否可查、是否发生混版、是否给出可操作的恢复提示，以及最终任务结果。 |

对照组使用相同任务、模型版本、预算和工具，分别跑关闭 Skill、显式调用、自动选择三种条件。首轮采样覆盖上述每类，记录重复次数、样本数、分母、延迟、token 和失败原因。机械权限／版本用例要求全部通过；效果提升按既有效果计划的基线和采用门槛判断，样本不足标为探索结果。GitHub 真实验收使用明确记录的公开仓库、子目录与 commit，至少完成一次成功安装；鉴权与限流另用 MockTransport 稳定覆盖。

| 变更范围 | 最小回归与发布检查 |
|---|---|
| 解析、角色、会话与依赖版本 | 先跑 `uv run pytest tests/test_skills.py tests/test_skill_install.py tests/test_session_context.py tests/test_context_assembler.py tests/test_context_engine.py tests/test_orchestration_m6_m9.py`。补同名、跨会话、fork、child、手动后读引用、脚本审批、升级旧 journal 和恢复用例。涉及 Session、配置、Runtime 后跑全量 pytest。 |
| Host 与上传 | `uv run pytest tests/test_workspace_host.py tests/test_web_api.py`。补未认证、Origin、过期预览、重复确认、两客户端并发、取消、写入失败与恢复；断言磁盘内容、effect 和工具目录，而非仅检查 HTTP 响应。 |
| Web、桌面与 TUI | Web 执行 `pnpm --dir src/web test`、`typecheck`、`build`（后两项同目录）。浏览器和桌面各完成一次导入与恢复；验证键盘选择、失败保留草稿、安装后即时可见。若改 TUI，再跑交互及 snapshot 回归。 |
| 契约与交付 | Python 执行 Ruff、Pyright；更新并核对 contracts、OpenAPI／TS、受影响的 Atlas。同步作者指南、命令说明、配置示例和架构文档。涉及打包时先构建 Web，再构建 wheel，在隔离安装中核对资源与 CLI。 |

发行顺序为内部夹具 → 受信项目试用 → 启用受管用户范围的试用 → 满足门槛后开放对应入口。各阶段使用临时工作区做安装、覆盖、失败和恢复演练。回退先关闭新导入或共享发现，保留已有文件与可读历史；回滚单个安装使用上一个已验证目录快照，若已有本地修改则保留并提示冲突。历史 Session 的二进制降级遵循 M2 的实测兼容矩阵。

## 5. 优先级与范围决定

- **首个可交付修复是 M1**。它解决用户明确选择后仍无法完成任务的问题，同时堵住第三方手动限制被忽略的兼容缺口。**首个完整产品版本为 M1–M3**，包含导入入口、版本变化提示和即时调用。
- **M4 可延后**。共享目录默认关闭、操作界面只移除受管安装，是本计划提出的默认取舍。首版不依赖 npm 包管理、插件市场、云同步、自动安装系统依赖或复刻 Claude 的 fork／动态执行语义。这些能力应各自有用户场景、权限契约和成本依据。
- **M5 的证据决定推广范围**。执行协议通过即可认定对应入口可用；宣称模型“更会选技能”须有真实对照数据。由维护者在 M1 合并、M3 试用、M5 推广三个节点分别登记提交、测试环境、实际结果及开放问题。

### 真实模型对照

使用配置中的 `openai:k3.1-pro` 路由，七个合成任务各跑关闭、显式调用、自动选择三种条件，共 21 次。任务包括引用、近义改写、声明脚本、手动包、缺失引用、已停用包和无关问答。每次使用新工作区和会话，固定打乱次序，每次最多 5 次模型请求、6 次工具调用。显式组在存在预期且可用的技能时先激活。关闭组仍可使用原有的工作对象工具访问项目文件。试验只记录合成任务的评分和工具轨迹。

| 条件 | 完整回答精确匹配 | 回答包含预期值 | 运行失败 | 耗时中位数 | 输入／输出 token 合计 |
|---|---:|---:|---:|---:|---:|
| 关闭 Skills | 4/7 | 5/7 | 2/7 | 10.32 秒 | 53,158 / 1,779 |
| 显式调用 | 5/7 | 7/7 | 0/7 | 8.96 秒 | 67,409 / 2,080 |
| 自动选择 | 6/7 | 7/7 | 0/7 | 8.09 秒 | 71,268 / 1,891 |

自动组在四个应选任务中全部加载预期技能，三个不应激活技能的任务均未加载任何技能。引用和中文改写均走通读取。脚本成功执行并返回预期值，回答附带其他文字，因此未通过精确匹配。显式组还有一条手动包回答出现同样的格式偏差。关闭组有一次借助通用工作对象工具找到引用答案。每种条件每题只采样一次，未采集计费数据，表中的延迟与得分仅描述本轮。

另外用同一路由验证一个手动包的多轮恢复，每个阶段都重建 ResourceManager。第一次试验中，初次选择能读 V1，原文件变化后收到重新选择提示，明确重选后能读 V2，撤销来源后报告不可用，四个回答均符合预期。这次请求了压缩，journal 中未观测到新的持久检查点。

第二次从预置且已持久化的兼容压缩检查点开始恢复。四次运行均保留检查点，更新前后的读取隔离和撤权生效。回答四次中有三次符合预期。明确重选后的一次，模型没有调用资源工具，也没有返回新版代号。该样本说明仍需积累长会话中的工具使用数据。两轮都没有观察到用户重选之前返回新版文件字节。

复跑七题对照的命令为 `uv run python scripts/benchmark_agent_loop.py --skill-eval --config agent.yaml --execute --repeats 1 --output results.json`。该命令会访问配置的真实 Provider。[本轮逐次记录](../research/2026-11-20-skill-lifecycle-evaluation.json)

### 验证与回退

- macOS arm64 上，包含 `web`、`live` extras 的全量 pytest 为 **1667 通过、1 跳过**，其中 60 个快照通过。跳过项是单独启用的 Crawl4AI 在线渲染测试。Web 为 **308 通过**，类型检查与生产构建通过。Ruff 与 Darwin／Linux／Windows 三种 Pyright 平台配置通过。wheel 在隔离环境验证 CLI、配置、内置 Skills 和 Web 静态资源。
- Contract、Provider 目录和架构 Atlas 的新鲜度检查通过。OpenAPI 的 Git 比较显示本轮新增路由及类型的预期差异；重新生成后，OpenAPI JSON 和 TypeScript 文件的 SHA-256 值分别保持一致。
- 已用基线提交的真实 v13 reader 检验降级。它能读原始 v13 journal，在追加 v14 激活后会拒绝该 journal。首次升级前备份会话目录及相应 artifact；需要回到 v13 时，在副本上恢复配套的升级前数据。手工删除 marker 会破坏历史一致性。
- 发现或导入功能可分别通过关闭共享根、停用具体来源或从 `tools.builtins` 移除 `install_skill` 回退。受管目录的历史版本通过 TaskWorkspace 快照恢复。macOS 原生 WebView 和桌面后端已覆盖，安装版 Tauri 壳及 Linux／Windows 原生运行仍属于发布验收。
