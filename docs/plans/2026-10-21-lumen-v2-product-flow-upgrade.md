# Lumen v2 目标驱动与资料空间优化实施计划

日期：2026-10-21。状态：本地实现已落地；P4 发行门禁部分开放。正文保留实施前的意图，实际实现与取舍见第 12 节及[验证记录](../research/2026-10-21-v2-product-flow-validation.md)。依据为[真实产品研究与升级前审计](../research/2026-10-21-muse-chatgpt-space-product-research.md)。本计划接替 r2 的文件自动化入口方向；现行运行契约以源码和[第 16 章](../architecture-guide/16-personal-assistant-automations.md)为准。

目标：用户从一句委托、一个目标或一份资料开始，能在同一工作上下文内规划、执行、检查结果和继续修改。需要周期性工作时，再把已验证的工作设为持续跟进。保留当前 Lumen 配色、Geist、动态九尾狐及既有执行／权限体系。

## 1 必须改变的产品决定

1. 目标创建不要求文件、调度或手写里程碑。先填“想达成什么”，补充说明可选；Agent 在关联对话中提出计划，用户可以确认和调整。
2. 自动化移出主导航；用户可在目标／资料详情设置持续跟进，也能从活动入口查看和暂停全部跟进。旧 CLI、API、定义和运行历史保留。
3. 资源库演进为资料空间：先支持现有报告／笔记的阅读、版本编辑、关联目标和上下文讨论，再补资料集合及受支持的导入。执行临时文件不默认充当用户成果。
4. 对话、目标、运行、来源和成果通过稳定 ID 关联。“继续讨论”不再只拼接正文并丢失原对象身份。
5. 普通规划可没有外部资料；检索新闻需要真实联网能力；整理选定文件才需要文件。不能将 `paths` 改为可空就声称支持通用后台 Agent。
6. 内容保存、执行完成、目标达成、持续跟进启用分别有明确状态。一份报告生成成功，不自动勾选长期目标已完成。

## 2 导航与页面职责

| 入口 | 用户看见什么 | 首要动作 | 必须能去哪里 |
| --- | --- | --- | --- |
| 对话 | 当前委托、相关目标和资料、真实运行结果 | 发送／继续；保存成果；设为目标 | 对应目标、同一资源详情、运行活动 |
| 信息流 | 新成果、值得关注的变化、需要处理的事项 | 查看结果／处理问题／继续讨论 | 原目标、固定资源版本、原执行 |
| 灵感 | 有理由的建议及关联目标 | 先讨论／采纳；忽略／恢复 | 带上下文的对话或新目标草稿 |
| 目标 | 当前结果、下一步、相关对话和成果、跟进安排 | 继续推进 | 目标对话、资料、最新运行、跟进控制 |
| 资料空间 | 已收录成果与资料；最近、收藏、类型及集合 | 打开／编辑／围绕此资料讨论 | 所属目标、原对话、来源和版本 |
| 头像旁活动入口 | 正在执行、排队、失败、全部持续跟进 | 停止本次／暂停跟进／处理阻塞 | 原工作对象与诊断详情 |

活动不是新增一个主内容菜单。所有持续跟进，包括未关联目标的旧任务，都能从这里进入；暂停不能只藏到高级设置。预算、owner、执行 Profile 等技术详情放入展开区，用户默认只看范围、下次执行时间和本机是否在线。

资料空间初版不展示“与你共享”、协同在线状态或未支持的幻灯片／表格创建。默认按真实最近活动排序；列表／网格是同一查询的展示，不维护两份资源状态。集合称“资料夹”或“集合”，避免与磁盘 workspace 及运行隔离混淆。

## 3 三条端到端主流程

### A 从目标开始 不选文件也能规划

1. 用户点击“新建目标”，输入“每天跟进值得关注的 AI 新闻”。只要求意图，不要求先写行动方案。
2. 保存 Goal，进入该目标的关联对话。页面明确区分“现在整理一次”与“设置持续跟进”；不把名称里的“每天”自动当成已经启用的计划任务。
3. Agent 确认关注范围和可用来源，提出可执行计划。当前模型若没有可验证检索能力，显示缺口及配置入口，不要求上传一份无关文件，也不伪造新闻。
4. 用户选择“现在整理一次”，通过原 StartRun 执行；成功报告作为明确成果收录资料空间，关联原 Goal／Session／interaction。
5. 目标详情出现“最新简报”和“继续推进”；信息流打开相同资源 ID 和本次固定版本。失败则保留问题与重试入口，不显示成功简报。
6. 用户需要每天跟进时，在目标详情设置时间并查看范围摘要；试跑通过后明确启用。下次执行、暂停、最近结果在原目标中可检查。

即时整理可先复用普通交互现有联网能力；后台联网必须完成第 7 节的受限执行升级。两者不能混淆发布。

### B 从对话成果开始 不重新输入上下文

1. 用户在对话中明确要求生成报告，或对已生成内容点击“保存到资料空间”。普通问答不自动建页面。
2. Host 发布／收录一个 Resource 引用，返回可打开的卡片。保留 origin Session／turn 和正文版本，不另复制成无法追踪的笔记。
3. 用户打开内容，选择“继续修改”。桌面采用内容＋关联对话的双栏；手机采用详情／讨论切换，保留资源与草稿。
4. 提交修改时携带 resource_id 和 expected_revision。Agent 的修改先以候选结果展示；应用后检查实际内容和版本。冲突保留草稿，要求重新核对，不能覆盖另一处编辑。
5. 若从这里创建目标，资料作为明确上下文引用关联目标。返回原对话或目标时，打开同一个对象。

### C 从资料开始 不把所有文件当执行前置条件

1. 用户可以先建空白页面、保存笔记，或收录已有成果。只在确有资料时选择添加。
2. 从资料详情发起总结／修改／创建目标，带 Resource 引用和“使用当前版本／使用最新版本”的明确规则。
3. 导入文件必须显示解析状态；能上传、能预览、能供模型读取是三种不同能力。未解析成功的 PDF／DOCX 不显示为已读。
4. 收藏、加入集合、重命名与从列表移除仅操作索引，不改写原 Work Product、journal 或源文件。
5. 资料的持续更新仍通过显式的跟进定义。页面正文写“每天更新”不是调度成功回执。

## 4 页面与交互要求

### 4.1 目标详情

显示用户意图、成功标准、确认的里程碑、下一步、相关对话、资料和跟进。没有计划时显示“与 Lumen 一起规划”；已有主对话时显示“继续推进”，不会每次新建对话。

新目标允许空 milestones；用户可直接提供已有计划，也可让 Agent 提议。模型建议与用户确认分别展示。完成百分比仅由已确认里程碑计算，不能将模型执行次数或文字判断当作完成度。

“暂停目标”若涉及多个持续跟进，先展示受影响列表和具体动作；“停止本次执行”只取消当前 run。暂停、取消和归档不互相冒充。

### 4.2 资料详情与编辑

首轮继续使用已有 Markdown 渲染和文本编辑，不先引入完整块编辑器。页面顶部显示类型、关联目标、来源、版本与操作；对话中和信息流中的资源卡片都打开此详情。

报告／笔记沿用 Resource 的 CAS 编辑权威；Work Product 沿用 TaskWorkspace，不能通过通用资料编辑绕过其验证。交互 HTML 使用现有受限预览边界；索引中有 HTML 不等于可以不受限制地执行页面脚本。

局部选区 AI 编辑可在完整版本编辑稳定后增加；届时必须验证目标范围与非目标内容，不能只在前端截取一段再覆盖整篇。

### 4.3 信息流与灵感

信息流至少携带 goal_id／resource_id／occurrence_id 中实际存在的关联，展示具体进展与下一步，不只显示“资料整理已完成”。无需处理的普通成功可以安静；来源失败、预算中断和需要选择的事项应有可操作详情。

灵感先使用可解释规则：来自未完成目标、未完成的资料整理或明确的用户选择；理由和关联对象可见。不要用“持续理解你”的文案冒充已实现的主动学习。采纳建议记录其目标／资源关联；只进入讨论的操作不自动启用后台任务。

### 4.4 导航、草稿与深链

提供可返回的目标／资源路由，例如 `?view=goal&id=...`、`?view=resource&id=...`；现有 `?session=` 继续工作。ID 必须经 Host 验证，URL 不是访问授权。

切换菜单保留讨论上下文和未提交草稿；关闭时必要的草稿决策沿用既有模式。返回键回到原列表筛选、滚动和焦点。开始建议只填草稿还是实际启动执行，按钮文案必须准确，不能悄悄覆盖已有输入。

## 5 数据与单一权威

扩展现有深 Module，不创建 AssistantRuntime、通用 TaskRun 或新对象图服务。下列字段和命令是待实现契约，不是现有 API。

| 对象／关系 | 建议最小增量 | 权威与约束 |
| --- | --- | --- |
| Goal | intent、状态、可空 primary_session_id；里程碑仍可为空 | AutomationStore 持有；旧记录缺字段按默认值读，不伪造已执行状态 |
| 目标与资料 | goal_resources 关系，区分 context／output | Store 持有，Resource 不再保存另一份互相矛盾的目标列表；反向关系按查询派生 |
| 持续跟进 | 继续使用 Definition；Goal.automation_ids 保持现有关联权威 | UI 投影为跟进安排，不另存一套定时器；未关联目标的定义也保留可管理入口 |
| Resource | 现有正文引用、origin、revision；增加收录／隐藏状态及真实活动时间 | note／report 投影为可编辑页面，无需同时增加一个同正文的 Page 权威 |
| 集合 | Store 中集合对象及 collection_resources 关系 | 仅本地组织；成员关系不授予额外来源权限 |
| 运行关联上下文 | 严格 ContextRef 与 admission 快照，关联固定 interaction | 选择与业务关系放助理库；Session 仍持有执行事实，ArtifactStore 持有正文 |

ContextRef 至少区分 Goal、Resource、现有 Session 引用，带必要的 workspace／object identity、版本选择和来源角色。持久化有界引用及摘要，不把所有资源正文、全量历史和 Memory 复制到 Goal。

工作区归属与读取权限必须在解析时检查。跨工作区引用明确拒绝；旧自定义共享 Session 目录不因此扩大可见集合。资料被隐藏、归档或源会话删除时，引用变成可解释的不可用状态，不偷偷搜索一个同名文件替代。

## 6 Host 接口与前后端贯通

| Interface 增量 | 行为 | 涉及入口与验证 |
| --- | --- | --- |
| CreateGoal／UpdateGoal | 保存意图及可选计划；严格输入、CAS 和请求幂等 | `automation/models.py`、Store、Host；新增／旧目标兼容测试 |
| ContinueGoal | 返回主对话或可靠建立关联；可只打开，不默认付费执行 | Host 统一持有 Session identity；重复点击／响应丢失不能新建多份对话 |
| StartAssistantRun | 用户显式启动，携带 ContextRef 和交付意图 | Host 解析范围后进入原 StartRun／Coordinator；无引用的普通对话保持原契约 |
| PublishAssistantResource | 收录用户明确要求保存／交付的内容，关联原执行与目标 | 来源所有权、正文存在与结果验证；与关联、信息流投影同一 Store 事务 |
| GetGoalDetail／ResourceDetail | 查询实际关联对象和最新进展 | 后端查询投影，不让前端扫描最近 200 条记录推断关系 |
| SetGoalFollowUp | 准备／试跑／启用／暂停现有 Definition | 原调度事务与审批规则；确认卡回显范围、时间及实际启用回执 |
| Collection／Visibility edits | 资料分组、收录和隐藏 | 不删除原正文，不影响恢复记录；服务端分页、稳定排序 |

P1 先复用 RunInput 已有 prepared model_prompt Seam 和普通 Context prepare 路径承载有界引用说明，不新增另一套 Loop。正文标注为不可信资料，原用户意图单独保留；ContextEngine 继续执行预算管理。执行结果由 Coordinator 持久化后才发布和收录。

ContinueGoal 需处理“助理库关联已准备、Session 尚未创建”的中断：预先持久化固定 Session UUID／请求 identity，复用现有独占创建和恢复实践；重试核对实际 journal，不从浏览器生成临时 Session 后猜测归属。Store 不可用时，有关联要求的操作明确失败，普通无关联对话仍可继续。

React 的 `onDiscuss(string)` 应演进为严格的讨论上下文参数，携带 intent、goal/resource 引用、打开还是启动。不得继续把正文和授权描述混成一段新的用户命令。

## 7 从文件自动化升级为可选择的受限执行方式

### 7.1 保留旧方式 新增真实只读研究方式

| 方式 | 来源 | 模型可用能力 | 文件是否必需 |
| --- | --- | --- | --- |
| 普通目标规划／即时执行 | 当前对话、显式选择的资料、已配置工具 | 原普通 Runtime／审批／Sandbox | 否 |
| 旧 workspace_snapshot | 旧 paths 对应文件快照 | 保持当前后台无工具语义 | 是，仅此方式要求 |
| 新 research_readonly | 明确主题、检索范围、可选资料及实际检索 receipt | 仅经验证、已授权的读取能力集合 | 否 |

背景工作仍按单 owner、单工作区执行席位排队。目标字段不拥有权限；自然语言“帮我全自动处理”不能放开工具。

优先复用已经配置的内建 web_search／web_fetch，经 Gateway 收窄；只有 read／observe、无需临时确认且符合来源范围的工具可进入 Profile。对只有 Provider 原生搜索的配置，必须在既有 ModelDriver Seam 证明该原生能力的请求参数、范围、取消与 usage receipt 后才能启用；此前明确显示后台不支持，并保留前台执行，不偷偷切换服务商或外部账号。

`BackgroundExecution` 从单一请求数约束扩展为不可变的有效能力／来源约束。`Runtime._lumen_tool_schemas`、实际 Gateway、ModelDriverRequest.native_tools 和预算必须一致收窄。保留旧 snapshot Profile 的空集合，不把所有后台任务改为拥有全部 read 工具；工具的参数范围、MCP unknown effect 和原生工具需分别验证。

### 7.2 持续跟进的定义与试跑

新定义使用有版本的严格输入，区分 sources／context_refs 与旧 paths。旧 paths 映射到 workspace_snapshot；新研究方式以查询主题和范围驱动。不是把旧 paths 设成空元组后交给同一读取函数。

准备跟进时生成可读摘要：做什么、读哪里、产出到哪份内容／信息流、何时执行、何时通知、何时结束。高级区再显示步骤／工具次数／执行时限；这些限制仍真实生效。

试跑结果有明确覆盖与产物，只验证本次配置，不消费正式 checkpoint，也不显示已启用。正式启用后显示真实 next_due 与 owner 状态。改变执行意图、权限范围或执行方式使验证失效；重命名、勾选普通里程碑等不改变执行语义的动作不应无故清空验证。定义 CAS 与执行指纹各司其职，避免重现控制 revision 与排队 admission 冲突。

### 7.3 来源、投递、去重与取消

每次读取形成 receipt：实际来源标识、读取时间、覆盖／错误和正文 artifact 引用。新闻使用返回的来源 URL 和可验证时间，不把搜索无结果、授权失败或解析失败当作同一结果；无法确认发布时间的条目明确标注，不冒充今日新闻。

默认保留有意义的新结果，不再仅用文件 hash 判断业务 no_change。早期宁可明确交付成功结果，再增加经过验证的等价规则。后续新闻去重需要来源项身份、内容版本与本地日期／提醒语境；日期相关事项不能因文件未变被隐藏。来源失败保留其 checkpoint，资源、信息流及成功来源状态在原 Store 事务结算。

停止必须取消实际 run、等待 Coordinator 的持久终态，再释放席位。暂停安排只影响未来／未开始实例；重启仍核对 fixed interaction，不重放未知执行。需要用户选择或授权时记录可操作 blocker，不在无人值守任务中等待内存审批 Future。

本轮仍只做站内交付；邮件发送、购买、账号 OAuth、持久审批 continuation 和云常驻保持后续范围。Host 退出／休眠时不运行，不能宣传等同 Muse 云端在线。

## 8 迁移与兼容

1. 自动化库从当前 schema v1 迁移到必要的下一版本：事务增加字段默认值／关系表，迁移前备份，未知版本或损坏库继续 fail closed。不要先改 user_version 再补表。
2. Session v12、配置 v2 不为导航调整升级。关联选择保存在助理库，正文在 ArtifactStore，原 journal 不重写。若实现确需新增 journal record，应单独评审 schema，不能把新字段悄悄写进旧版本。
3. 旧目标补充主对话时由用户触发 ContinueGoal，不全量自动开会话；旧自动化保持原 id、状态、时间和来源，不因升级自动启用或暂停。
4. 旧资源逐步改为“待收录／旧执行材料”的可见性投影。历史全部可从原会话或显式“执行材料”筛选找回；已收藏内容保留可见。新成果由显式发布／保存进入默认列表，不靠删除临时文件清理视图。
5. 旧 `/assistant/automations`、CLI 及 request identity 保留为同一权威的 Adapter，明确新能力边界。旧路径或旧书签打开兼容的跟进详情，不形成第二个 Scheduler。
6. 排序使用真实内容活动时间与稳定 ID 游标；启动扫描不把历史全部标成刚更新，不因同一路径多次执行产生难以区分的默认列表项。

## 9 实施顺序与退出条件

不按界面页数验收，也不以“菜单都有了”为完成标准。以下按依赖顺序交付，可在对应阶段独立验收，不虚构日历工期。

| 阶段 | 实施范围 | 退出条件 |
| --- | --- | --- |
| P0 可靠性修复 | 修复既有审查四项问题：排队启用、no_change、notify 保留、工具重名 | 四个反例成为正式回归；旧暂停／恢复／权限契约保持；见[原审查](../research/2026-10-20-v2-code-review.md) |
| P1 真实一次性闭环 | Goal 意图与关联会话；ContextRef；成果发布／关联；资料默认清噪；五项导航、活动内兼容旧安排 | 不选文件可创建并继续规划；同一目标两次继续进入同一关联上下文；一次成功交付可从对话／目标／资料三处打开同一资源；失败不造成功状态 |
| P2 持续跟进与联网 | research_readonly Profile、来源 receipt、无文件试跑、目标内时间设置和全部跟进控制；受支持来源缺口可见 | AI 新闻样例真实检索并生成有来源简报；启用／暂停／漏跑／重启后可核对；工具／原生能力矩阵证明无权限扩大；不依赖手写文件路径 |
| P3 资料工作流完善 | 集合、受支持导入、全文检索、版本编辑与可选选区修改；移动端与返回路径 | 资料→讨论→修改→关联目标→重新打开闭环；并发编辑保护、坏文件／失效引用、分页、键盘与手机可用 |
| P4 发布验收 | 更新 Accepted 说明、OpenAPI／contracts／Atlas、Web、wheel、桌面元数据和用户指南 | 真实 Provider smoke、目标平台 CI、用户主流程实测与既有发行门禁通过；不把 mock／原型当生产验收 |

P1 是最小可演示切片：先打通对象关系，再扩大后台能力。P2 未完成前不能把文件自动化包装为已支持全网新闻跟进；P3 的“导入”只展示已经实现的格式和解析能力。

## 10 验证矩阵

| 场景 | 必须断言 |
| --- | --- |
| 无资料目标 | 仅意图也可保存、规划；没有伪造来源或自动启用计划 |
| 已有目标 | 修改／继续／关联资料可用；CAS 冲突不覆盖；历史目标可加载 |
| 重复继续 | 网络响应丢失／重启后同 request identity 不生成重复关联会话 |
| 上下文串联 | goal/resource/revision 到达真实模型请求；跨工作区或不存在引用拒绝；普通对话路径不受影响 |
| 资源发布 | 临时写文件仍在 journal，但不默认成为成果；明确发布的同一资源可从多入口打开 |
| 内容编辑 | 原版本可核查；冲突保留用户草稿；Work Product 仍由 TaskWorkspace 验证 |
| 持续跟进 | 启用有真实保存回执及 next_due；暂停／取消不同；独立旧安排仍可找到 |
| 无文件联网 | 有能力时实际检索；未配置或权限不足时明确阻塞，不改用户模型／账号，不虚构查询结果 |
| 后台权限 | schema、Gateway、原生请求一致；确认型／unknown effect／越界参数拒绝；退出后普通能力恢复 |
| 结果语义 | 日期变化而来源相同的新提醒不丢；读取失败不当无变化；部分覆盖和去重依据可核查 |
| 生命周期 | 单 owner、前台竞争、睡眠／重启、结算失败、目录损坏与引用删除都保持可恢复事实 |
| UI 连贯性 | 回退、筛选、滚动、焦点、草稿保留；手机可继续同一工作，不重复提交 |

后端覆盖 Host／Store／Coordinator／Runtime／Gateway 实际组合；主链状态变更按 AGENTS.md 运行相关测试后全量 pytest，Python 运行 Ruff 与 Pyright。Host／API 加跑 workspace_host／web_api，生成 contracts／OpenAPI。Web 跑 test、typecheck、build，并在浏览器操作上面三条主流程；不能只验证组件“渲染成功”。打包仍先构建 Web，后 uv build 并隔离安装验证。

新增背景联网至少对一个真实已配置 Provider 与一种受限检索路径完成 smoke，记录覆盖、调用与成本事实；MockTransport 仅证明请求契约。缺少能力时先交付真实的一次性上下文闭环，不用模拟卡片补齐未实现能力。

## 11 完成标准与本轮交付

版本的完成标准是用户能连续完成 A、B、C，而不是五个菜单能切换：目标无需无关文件即可开始；继续工作保留身份；结果进入同一内容对象；持续跟进可查、可停、不会假称成功；资料空间能继续使用成果。

计划撰写阶段只完成研究；后续实施状态见下节，不以此前的 Proposed 状态否定当前实现。

## 12 实施记录与取舍

实现复用现有 EditAssistant 和 StartRun，没有逐一增加正文中所有暂定命令名。新增 GetGoalDetail、ContinueAssistantDiscussion、PublishAssistantResource；关系、集合、可见性沿用 Store 的单一事务权威。

后台研究采用比原提议更窄的来源收集方式：固定查询、最多 5 条摘要和 3 个网页节选，模型阶段仍无工具。这样既支持有真实来源的研究，也保留 snapshot 原有隔离语义；本轮没有将 Profile 扩展为任意自主浏览器或 Provider 原生联网。用户当前工作区未配置内建检索，不在升级时替用户添加服务或放宽权限。

全文搜索覆盖新笔记、发布回答和后台结果的正文；旧未索引执行材料按标题检索并从原会话核查。导入只接受已实现的至多 100 KB UTF-8 文本格式，不提供 PDF／DOCX 已读假象。选区 AI 修改、富文本块编辑、共享及外部投递没有作为本轮完成能力。

资源正文、Session 和 TaskWorkspace 权威保持分离。助理库迁移 v1→v2，先备份再事务变更；Session v12／配置 v2 不变，旧 API／CLI 继续投影到同一 Scheduler。
