# Web 过程展示：ChatGPT 参考审计与实现决策

日期：2026-09-03。范围：现有 Web 对话中的公开过程、工具活动、完成折叠与耗时。

## 参考证据

- 用户提供的两张截图：展开时，进展正文与带图标的工具活动交错；完成后，仅留下耗时折叠入口，最终回答独立显示。
- [用户指定的 ChatGPT 页面](https://chatgpt.com/c/6a977dd9-71a0-83ec-a467-f4d3eeed18ad)：实际打开同一条“思考了 2m 35s”记录，分别捕获展开和收起状态。截图位于 `outputs/process-ux-2026-09-03/01-chatgpt-collapsed.png` 与 `02-chatgpt-expanded.png`，视口 1920×832。已完成记录不能用于验证实时结束的过渡；这部分以用户描述作为目标，在 Lumen 中验证。
- 当前 Lumen 运行中页面：`03-lumen-before.png`。默认收起，手动展开后为 360px 内部滚动框，小号灰色正文、重复“思考”标签、卡片式工具详情。
- [OpenAI 对工具与推理交错的产品说明](https://openai.com/index/introducing-o3-and-o4-mini/)支持将模型处理与工具使用视为同一个过程。具体排版与折叠行为以现场截图为依据，不推断 ChatGPT 内部实现或计时算法。

## 差距与决策

| 现状 | 用户影响 | 更新后的行为 |
| --- | --- | --- |
| 活动默认收起 | 运行中看不到进展 | 运行中默认展开，可主动收起；新审批自动展开 |
| 过程正文小且淡，重复类型标签 | 长内容难读，像调试日志 | 与回答共享正文大小、颜色、Markdown 层次；去掉重复标签 |
| 过程内独立纵向滚动 | 滚动嵌套，中间输出被截断 | 跟随主对话自然排版，不限制过程高度 |
| 每条工具卡同时显示类型、技术细节、状态 | 主阅读面噪声过多 | 图标 + 动作与目标为单行入口；参数和结果按需展开 |
| 中间 assistant 文本依赖后续最终回答才归类 | 流式阶段位置不稳定 | 后续工具出现时即归入过程，保留顺序与原始 journal |
| 结束只显示活动条数 | 无法判断处理时长 | 显示 Runtime `UsageUpdated.elapsed_seconds`；流式投影与历史回放复用同一事实 |

## 状态契约

- 成功结束：收起过程，最终回答始终在外；之后用户可重新展开，后台更新不重置选择。
- 失败、取消/中断、等待用户补充：默认展开；错误/补充问题仍在前台。
- 待工具审批：自动展开，审批按钮保持可用；批准后的历史预览与结果按需查看。
- 没有过程的普通回答不创建空面板；正在等待首个输出时使用现有运行状态。
- 耗时表示整轮模型、工具及相关等待的实际处理时间，不宣称是纯模型思考时间。缺失、负数、非有限值不显示。旧记录可读，不改写 Session，不新建计时状态权威。
- 保留 Lumen 品牌、计划面板和权限语义；工具图标使用现有图标库与已声明 family，不复制外部产品商标。
