# Lumen + OpenViking 长期记忆试点验收

2026-11-26，在本机 Docker 的 ARM64 环境运行 OpenViking v0.5.6，仅使用合成记忆与独立试点凭据。Docker 虚拟机可用 16 个逻辑 CPU、约 7.65 GiB 内存。向量模型为 Ollama `qwen3-embedding:0.6b`（1024 维），目录处理和答案抽样使用 `qwen2.5:0.5b`。所有统计仅代表本次部署。配置及回退步骤见[记忆命令](../commands.md#21-memory-actions)。

## 服务契约与恢复

- 通过真实 Lumen 根 Host 和临时 SQLite 执行项目授权、记住、后台同步、遗忘、移除在线副本。分别核实同步变为就绪、清理队列收敛。v0.5.6 的 `/health` 返回带 `v` 前缀的版本号。
- 用同租户两个不同用户的 key 检查同一私有对象，拥有者读取返回 HTTP 200，另一用户返回 403。不限 300 ms 的两次中文改写查询均取回目标，约耗时 2.74 和 2.77 秒。
- 在早期同步试验中，一次等待索引完成的写入约耗时 26.6 秒，等待完成的删除在 120 秒超时，稍后精确查询该 URI 已返回 404。客户端使用异步写入及逐 URI 删除，单独核验在线对象已不存在。同步就绪表示已收到写入回执，向量索引可能稍后才可检索。
- 重启、双 Host 租约竞争、丢失回执、撤权、隐私暂停和迟到写入用本地 SQLite 及受控 HTTP 回执覆盖。可用性以本地状态为准，记忆遗忘后在下一次模型请求重新检查，远端清理可延后完成。在线删除的验证范围不包括运营方备份。
- 溢出索引试验暴露了旧版 SQLite FTS5 触发器的行号问题，编辑和使用计数更新可能使词法查询报错。现有数据库首次打开时会在事务内重建派生索引。回归从可复现故障的旧库开始，覆盖重建后的检索、编辑、遗忘和 FTS5 完整性检查。远端已就绪文件丢失时，后台会限速核验，只重新排入仍有效且获准的当前版本。

## 模型调用与存储

在同一隔离服务停止其他试点流量、等索引任务完成后，单独写入 5 个新版本，接着顺序执行 10 个查询。统计服务端模型的 HTTP 请求数，磁盘读取 Docker 容器内 `du -sk /data` 的差值。

| 操作 | 实测 | 按每千次线性折算 |
| --- | --- | --- |
| 写入 5 条短合成记忆并等待处理 | 5 次 embedding，0 次生成，数据目录增加 116 KiB | 1000 次 embedding，约 22.7 MiB 磁盘增量 |
| 已预热索引查找 10 次 | 10 次 embedding，0 次生成，每次返回 5 个文件候选，耗时 23.1–66.7 ms | 1000 次 embedding |

这次计量使用本地模型，无按次 API 账单。磁盘增量包含数据库页分配，不能据此预测长期容量。目录生成、冷启动、同时同步与查询、云模型单价均会改变实际成本和延迟；上文早期两次改写查询已超过 300 ms。复测时应保留队列是否空闲及部署区域、并发、模型缓存状态。

另建一个单条目索引并等待队列清空，卸载 embedding 模型且确认其已退出后做三次不同表述的查询。直接调用 HTTP Adapter 时，首次冷查询耗时 808 ms，随后两次热查询为 25.0 和 26.4 ms，三次均命中目标 URI。在产品的 300 ms 上限下，冷请求将使用本地回退。

## 评测口径与复测

A 重现旧固定索引的去重；B 仅按实际进入预算的条目去重；C 在 B 上启用有界语义召回。小索引有 3 条事实，溢出索引有 25 条事实，每条派生中文改写、英文改写、代码标识和无答案四种问题，共 112 个问题，每个版本使用相同标签、2048 token 窗口和分区预算。另加入受限、遗忘和另一项目的事实，检查跨范围注入。候选取回后，按实际进入上下文的完整条目评分。动态 Recall@5 与目标是否已在固定索引中展示分别统计。

在隔离服务的环境变量中提供租户用户凭据，运行以下命令。答案服务采用兼容 chat completions 的流式接口。脚本将每题的分组、命中、耗时与聚合差值写入指定文件，使用独立标签对比 B、C。试验后清理本次投影。

```sh
uv run python scripts/eval_openviking.py \
  --endpoint "$PILOT_ENDPOINT" --embedding-model qwen3-embedding:0.6b \
  --answer-url "$PILOT_ANSWER_URL" --answer-model qwen2.5:0.5b \
  --answer-stride 8 --output /tmp/lumen-memory-pilot.json
```

## 结果与发布判断

**交付本地索引修正，OpenViking 保持按范围显式启用。** 在长索引中，语义查询能找回大多数中英文改写，但无答案问题也频繁注入无关记忆。按计划的无答案和首 token 延迟门槛，本部署不适合默认启用。[逐题数据、分组统计及配对区间](2026-11-26-openviking-pilot-results.json)

下表为溢出组，每行 25 题。动态命中指目标出现在动态召回的前五条，可见指正确版本的 ID 与答案同时进入模型上下文。区间采用问题内配对、2,000 次 bootstrap。

| 问题 | A 动态命中 | B 动态命中 | C 动态命中 | A / B / C 目标可见 | C 相对 B 的动态命中差及 95% 区间 |
| --- | ---: | ---: | ---: | --- | --- |
| 中文改写 | 0 | 0 | 22 | 3 / 3 / 25 | +88 个百分点 [76, 100] |
| 英文改写 | 0 | 0 | 21 | 3 / 3 / 24 | +84 个百分点 [68, 96] |
| 精确标识 | 0 | 22 | 22 | 3 / 25 / 25 | 0 个百分点 [0, 0] |
| 无答案问题的无关注入 | 0 | 0 | 22 | — | 误注入增加 88 个百分点 [76, 100] |

小索引的 12 个问题全部跳过远端检索。溢出组 100 个问题各触发一次查找。举例来说，三种方式都把最早写入的发布受众记录放入上下文；对“事故经过保存到哪里”的改写，只有 C 找回了正确记忆；对发票币种的英文改写，三个版本均未把目标写入上下文。所有 336 次组装通过受限、其他项目、遗忘、旧版本和过期哨兵检查。

| 112 题全体指标 | A | B | C |
| --- | ---: | ---: | ---: |
| 上下文准备 p95 | 3.6 ms | 4.5 ms | 182.8 ms |
| 每题平均记忆 token（固定索引加动态召回） | 79.6 | 73.7 | 164.6 |
| 真实模型答案严格匹配（每组抽样 20 题） | 5/20 | 5/20 | 6/20 |
| 准备加首个答案 token 的 p95（每组 20 题） | 13,539 ms | 792 ms | 1,998 ms |

中文和英文检索收益达到了计划的 +10 个百分点门槛。无答案组允许的误注入回退为 2 个百分点，实测为 88 个百分点。五个抽样无答案问题中，三个版本均正确回答 UNKNOWN，但该样本无法排除其他模型受无关记忆干扰。整体答案严格匹配仅多 1 题。

B、C 各自的首 token p95 相差约 1,207 ms，逐题计算 C 减 B 的差值后取 p95 约为 1,620 ms，均超过 300 ms 目标。A 首测包含模型加载。小样本顺序测量包含模型推理和运行时波动，所测差值不能全部归因于网络。溢出组的记忆开销由 B 平均 74.4 token 增至 C 的 176.2 token。服务日志中的 100 次查找均返回 200，有 5 次在服务端耗时达到 300 ms；该批报告未保留进程内超时回退计数。

试点结束时，小索引的 6 个已派发版本、溢出索引的 28 个已派发版本完成在线清理。部署方可继续使用纯本地的 B 路径。

推广前在目标区域、实际模型及并发下，用至少 100 个独立标注问题复测 A/B/C。覆盖中英文改写、标识、否定与冲突、无答案、项目隔离、索引溢出和自然到期。门槛为 C 相对 B 的改写动态 Recall@5 至少增加 10 个百分点，精确标识命中下降及无答案误注入上升各不超过 2 个百分点，额外首 token p95 不超过 300 ms。分别记录小索引与溢出索引、冷启动与热运行、答案质量和单位同步成本。跨范围注入、隐私期间新发外部记忆请求、撤回后进入下一次请求、召回正文写入会话 journal 的次数都应为零。通过后再评估推广。

## 工程验收

发布分支从同一基线独立验证，Python 全量 1705 项通过、1 项跳过，60 个 TUI 快照匹配。Web 290 项通过，类型检查、生产构建、Ruff、Pyright 和生成物检查通过。下列较高的 Python 计数来自最初试点工作区，当时该工作区还有其他开发改动。

- macOS、Python 3.13.12，启用 web 和 live extras 的全量 pytest 结果为 1739 通过、4 跳过，其中 60 个 TUI 快照匹配。Ruff 通过，严格 Pyright 为 0 错误、0 警告。测试覆盖人工输入来源、后台与 headless 排除、实际派发前中止、重试前撤回以及投影恢复。
- Node 22、pnpm 10，Web 290 项测试、类型检查和生产构建通过。OpenAPI 和 TypeScript 类型重新生成前后 SHA-256 相同，contracts 与架构 Atlas 新鲜度检查通过。
- sdist 和 wheel 在 Web 构建完成后生成。在隔离环境安装 wheel，验证记忆模块可导入、CLI 版本为 2.0.0、显式指定启用连接的隔离配置可通过 `--check-config`。本次实测平台为 macOS ARM64，未运行跨平台 CI。
