# 页边滚动与异步标题

日期：2026-09-03。依据为用户提供的 ChatGPT 截图，以及 Lumen 当前源码和真实浏览器行为。

## 观察与决策

截图的原生滚动条靠页面右边，旁边的短横线提供消息位置线索。Lumen 原先把 `.timeline` 限制在 800px 阅读栏内，导致滚动条落在正文旁。现在滚动容器铺满对话区域，通过内边距维持正文阅读宽度；不拦截滚轮，也不模拟拖拽滚动条。桌面新增消息导航，用真实消息位置计算当前项，ResizeObserver 响应流式输出和内容折叠；点击与键盘定位退出自动跟随，回到底部恢复跟随。窄屏隐藏额外导航，保留原生触摸滚动。

原标题是同步截取输入；缺少生成状态，也没有延迟结果的所有权判断。现在 Host 在输入持久化后先追加“新对话”，记录来源 turn 索引，然后后台生成。正文不等待标题，标题请求无工具、无 Agent 执行权，输入最多 2000 字符并脱敏；并发上限 2、单次等待 15 秒，失败回退 40 字摘要。正常返回的标题不超过 80 字符，去掉引号与推理包装；空白、过长或标签输出回退。

Session catalog 是唯一持久化权威。后台结果写回前重读 catalog；手动改名清除来源索引，迟到结果不会覆盖。删除取消请求；关闭 Host 保留待生成索引，后续打开恢复。TUI、Web、headless 共享此行为。嵌入 Host 的最小 Resources 未提供生成能力时使用本地摘要；既有 Session catalog 无该可选字段仍可加载，schema 仍为 v9，旧文件不重写。

Web 每 1.5 秒只刷新目录，后台页面暂停请求，生成完成后停止轮询。列表刷新有递增请求序号，迟到请求不能覆盖手动改名后刷新出的新状态。页面标题、侧栏与浏览器标题同源；消息、SSE 和输入草稿不因标题变化重载。消息编辑分支由新接受的输入触发相同流程，删除前端同步重命名分支的重复逻辑。

浏览器验收另发现任务菜单把 `event.currentTarget` 放进延迟执行的 state updater，事件结束后引用可能为空，菜单永久隐藏。现改为在点击处理器内捕获 DOM 元素，再更新状态；重命名入口与迟到轮询回归覆盖此问题。

## 范围与限制

保留 Lumen 的品牌、字体和配色，参考截图的布局与交互，不声称复制 ChatGPT 私有实现。模型标题是独立的辅助请求，不算入正文 turn 的耗时和 usage；本地模型、网络失败都不影响正文。自动命名仅作用于未命名 Session，不批量修改已有自定义标题。运行中的旧服务需要重启后加载 Host 变化。

验收记录及截图见仓库根目录 `design-qa.md` 第三轮。
