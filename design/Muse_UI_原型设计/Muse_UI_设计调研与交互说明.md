# Meta Muse — 中文 UI 交互原型设计说明

> 产品调研时间：2026-10-20。此交付是基于公开资料独立制作的**教学研究型前端原型**，并非 Meta 官方应用、官方 UI 资源包或产品源码，也不保证与实时生产版本逐像素一致。

## 一、调研对象与设计结论

调研对象为 Meta 发布的个人 AI Agent **Muse**，而不是同名的音乐 / 设计软件。Muse 最大的产品变化是从“被动回答”转向“自主执行、后台跟进及主动建议”。其界面用消息流降低学习成本，再用独立区域分别管理用户的长期目标、个人信息流、推荐灵感、已生成产物及执行历史。

公开资料支持的核心导航结构为：Chat / Search / Feed / Ideas / Goals / Library。活动状态可通过代理头像展开，设置中包括 Connectors、Permissions、Data controls 等权限相关入口。

## 二、交付范围

| 页面 / 模块 | 主要内容 | 可操作的演示动作 |
| --- | --- | --- |
| Chat | 对话气泡、机票追踪结果卡片、外部动作审批卡片、底部输入框 | 发送模拟消息、新建对话、批准或拒绝审批 |
| Search | 搜索与结果列表 | 关键词实时过滤、跳转对应页面 |
| Feed | 个性化 Prompt 设置、资讯卡片、收藏、讨论 | 修改 Prompt、重新生成、收藏、转入聊天 |
| Ideas | 多类别灵感列表 | 按类别筛选、开始执行、更多类似推荐、不感兴趣 |
| Goals | 长期目标概览、进度条、里程碑清单 | 创建目标、查看详情、勾选里程碑、继续推进 |
| Library | 文档、报告、表格、指南、交互式产物 | 按类型筛选、打开详情、继续编辑 |
| Activity | 后台执行轨迹、步骤状态、权限历史入口 | 点击状态头像，展开侧边抽屉 |
| Settings | 通用、应用连接、权限、记忆、外观、数据控制 | 切换模拟连接、编辑记忆、主题切换、导出 / 重置演示状态 |

## 三、设计语言（独立复刻）

- **视觉方向**：白色主画布、浅灰层次、极简图标、柔和圆角、少量品牌蓝强调；支持深色模式。
- **主色**：`#0B72F3`；背景 `#FFFFFF`；文本 `#17191C`；二级文本 `#6C717A`。
- **关键组件**：左侧 6 功能导航 Rail、顶部 Agent 运行状态、审批卡片、聊天输入胶囊、卡片式信息流、目标进度条和右侧 Activity Drawer。
- **设计重点**：明确区分「已经执行」「正在执行」「等待用户批准」三种状态；对不可逆外部操作给予明确确认。
- **响应式**：桌面侧边 Rail；窄屏切换为底部导航。

## 四、推荐验收路径

1. 打开 `muse_ui_prototype.html`，从 **Chat** 查看 Muse 消息、航班追踪卡片和授权确认。
2. 点击页面右上角 Muse 状态头像，打开 **Activity** 执行轨迹抽屉。
3. 进入 **Feed**，编辑「你的 Feed Prompt」，点击保存并重新生成；测试收藏与转入聊天。
4. 进入 **Ideas**，切换分类，并用卡片上的「开始试试」进入对话。
5. 进入 **Goals**，创建新目标；点击任一目标调整里程碑状态。
6. 进入 **Library**，切换内容类型并打开一个资产卡片。
7. 进入 **Settings**，查看应用连接、权限控制和可编辑记忆，测试深色模式。
8. 缩小浏览器宽度至手机大小，检查底部导航和卡片布局。

## 五、范围与限制

当前为单 HTML、纯前端的可点击原型。演示的用户数据与服务行为属于虚构样例，没有访问 Muse API、Meta 账号、真实邮件、支付或订票能力；点击授权不会创建真实交易或预订。

个别设置、页面内容和演示稿源于公开的 UI 设计报道及功能介绍，而非对登录后真实生产应用的完整抓取。为了形成“整套 UI”，本原型补齐了部分交互流程和视觉细节；这部分属于**合理推演**，不能当作 Meta 官方的逐像素界面或确定实现。
